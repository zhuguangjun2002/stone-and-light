# 啤酒与葡萄酒的酿造过程 —— 现状体检与实施方案

> 2026-10-08。要在场景里把「麦→芽→糖化→煮→冷却→发酵→陈酿」和
> 「葡萄→压榨→发酵→陈酿」两条线**展示出来**。
> 第 0–1 节是现状体检（已查证到代码行），第 2 节是空间账本，
> 第 3–6 节是施工单。已定的三个决策见第 1 节末尾。

---

## 一、现状体检

### 1. 那些"小房子"是什么，为什么没标注

场景里的房子一共三批，主站只挂了 **6 条标注**（`src/town.js:682-687`）：

| 批次 | 数量 | 代码里有没有名字 | 主站有没有标注 |
|---|---|---|---|
| 酿酒坊六座 | 6 | 有（`src/town.js:47-55` 的 `BREW` 常量） | **没有**，只挂了一个总的"酿酒坊大院" |
| 教士住宅 | 16（南排 8 + 东排 8） | 没有 | 没有 |
| 葡萄园 / 酒花圃 | **0** | —— | —— |

六座的名字一直写在 `BREW` 里，但**只喂给了 `tools/brewery.html` 演示页**
（`brewInfo().buildings[].name`），主站的 `labels` 数组里根本没有它们。
所以在主站看到的是"一排长得差不多的红顶灰墙房子"，认不出是干什么的。

### 2. 为什么里面没有设备

`brewHouse()` 的第一行就是一块**实心盒子**：

```js
// src/town.js:123
g.add(solid(new THREE.BoxGeometry(w, h, d), wallMat, 0, h / 2, 0));
```

没有内壁、没有地板、没有分隔，也没有任何器具。窗是贴在墙外的薄板
（`src/town.js:159-165`），门是贴在墙外的薄板。教士住宅 `canonHouse()`
是同一个写法（`src/town.js:431`）。**整个领地里没有一件"屋内陈设"**。

### 3. 为什么门打不开

```js
// src/town.js:154-157
g.add(solid(new THREE.BoxGeometry(0.16, dh, dw), mats.wood, -w/2 - 0.04, dh/2, 0));
```

一块 16 cm 厚的木板**贴在墙面外侧**：没有洞口、没有枢轴、没有
`userData.door` / `userData.doorId`。而 `src/doors.js:19` 的 `collectDoors()`
只认 `userData.doorId` —— 全场景只有大教堂那五座门有（`src/facade.js:307`），
所以酒坊的门在门的系统里**根本不存在**，`K` 键、`E` 键、碰撞判定全都够不着它。
这是设计上的空白，不是 bug：酒坊从来只是"立面"。

### 4. 葡萄树上没有葡萄 —— 因为场景里根本没有葡萄树

全库搜 `葡萄|vine|grape` 只搜到一处带"藤"的东西，是**酒花圃**
（`src/town.js:275-282`）：

```js
// 酒花圃（东扩带北段，x -46..-8 / z -69..-58）：五行木杆 + 顶部铁丝 + 爬藤
for (let x = -43; x <= -11; x += 8) {
  for (const z of [-67.5, -63.5, -59.5]) g.add(solid(postG, mats.timber, x, 1.65, z));
  g.add(solid(new THREE.BoxGeometry(0.09, 0.09, 9.0), mats.lead, x, 3.2, -63.5));
  for (const z of [-65.5, -61.5]) g.add(solid(vineG, mats.tree, x, 1.5, z));  // ← 就是这两块绿方柱
}
```

你看到的"一排杆子拉铁丝、上面挂着东西"就是它 —— 每行只有**两个 0.22 m 见方的绿柱子**，
没有花、没有果、也没有酒花球果。**葡萄园从未存在过。**

> ⚠️ 顺带查出一处文档误导：`docs/brewery-research.md:26` 写"768 年……当地的**酒花园**
> 向修道院缴十一税"。德文原文是 **Hopfengarten（酒花园 = 啤酒花园，酒花）**，
> 不是葡萄园。Weihenstephan 的资料明确说那是"修道院附近的**酒花种植园**"。
> 这个译名把啤酒的原料写成了葡萄的原料，正是"葡萄树上没有葡萄"这个错觉的源头。

### 5. 酒花该放哪 —— 现在这个位置是错的

| | 现在 | 决定 |
|---|---|---|
| 位置 | x -43..-11 / z -67.5..-59.5（东扩带北段，夹在绕殿巡游道与教士住宅之间） | **搬进酒坊大院**：主圃在大院东头、巷边沿墙一行 |
| 离酿酒坊多远 | 直线 **90–130 m**，中间还隔着大教堂与东排住宅 | 30–60 m，从服务巷一眼能看到 |
| 为什么这是错的 | 酒花（hop）采下后极难保存与运输，历史上酒花圃**永远贴着酒厂**（Weihenstephan 768 年的 Hopfengarten 就在修道院"附近"；今天霍尔德劳的啤酒花农场也在酒厂二十分钟车程内） | |

旧圃那圈杆子保留在西边（教士住宅需要点绿），文档里改称"修道院菜圃里的酒花架"。

### 已定的三个决策

1. **酒花圃搬到大院**（主圃 + 巷边一行）。
2. **葡萄酒窖另起一栋独立建筑**（不与啤酒酒窖合并），于是 `BREW` 从六座变八座。
3. **展示做到「静态布景 + 标注 + 演示页」**，主站不加新按键。

## 三、施工单

### 第 0 步 · 文档与调研

1. 改 `docs/brewery-research.md:26` 的"酒花园"→ **酒花园（Hopfengarten，酒花）**；
   `README.md:447` 附近同步（"酒花架"没错，但没说清它长在哪儿、为什么长在那儿）。
2. 新写 `docs/wine-research.md`，照 `brewery-research.md` 的体例，落地三条依据：
   - **Clos de Vougeot**（西多会 Citeaux 修道院）：1109–1115 年买地、1212 年前圈墙、
     1160–1190 建**大酒窖 cellier**（半地下、八根石柱、橡木大梁）、
     1477 建**压榨房 cuverie**（四台巨型压榨机 + 双排酒槽）。
     → 我们要的正是这个组合：**葡萄园(clos) → 压榨房 → 酒窖**。
   - 中世纪北方（我们这个纬度）葡萄多是**低矮篱架**，不是波尔多高立木
     → 所以葡萄园做**低木桩 + 双铁丝 + 藤 + 垂串**，不是树。
   - 酒窖为什么半地下：恒温。我们的 h=4.8，**墙外压三级土坡**（`spec.berm`）就够读。
     不挖门前地坑：门外只剩 1.4 m，还要横过明沟，坑会把沟切开（原先"挖 1.2 m 地坑"的写法已作废）。
3. 引用列在页面底部 URL（沿用现有文档的规矩）。

### 第 2 步 · 空壳 + 真门（**最关键的一步**）

改 `brewHouse()`（`src/town.js:116-180`）：

1. **壳**：四片 0.5 m 厚墙 + 一块地坪板 + 原有两片坡板屋面，
   北面（贴巷那面 `x0`）留**真门洞** 3.6 × 3.6 m。
   （`wallWithOpenings()` 是尖拱的；方门洞用四块板拼更省事，
   把现在"贴板"那两行换成"挖洞 + 门楣"。）
2. **门接进 `doors.js`**：照 `src/facade.js:165` `doorAssembly()` 写个简易版 ——
   门组 `userData.doorId = 'brew-brewhouse'`、枢轴 `userData.door = {side, max}`、
   门板挂在枢轴里。`src/doors.js:10` 的 `DOOR_NAMES` 加八座的名字。
   加完自动获得：`E` 近门开关、关门挡人（`doorBlocks`）、`buildCollision()`
   会临时藏门扇（`src/main.js:574-580`）所以门洞真的能走进去。
3. **三个必须处理的副作用**：
   - `buildDoorPlan()` 的小平面图 viewBox 是 `X0 = -27 … +27`（`src/main.js:541`），
     酒坊门在 x ≈ 62 会**画到图外** → 给 town 门打 `userData.town = true`，
     在 `buildDoorPlan` 里 `continue` 掉，顺带改掉"五座门全关"那句文案。
   - `K` 键现在是"五座门全开 ⇄ 全关"（`src/main.js` 的 `setAllDoors`），
     加了 8 扇门之后会一次开 13 扇 → **K 只管教堂五座**，酒坊门走面板/近门 E。
   - 雨雪天 `WEATHER[].doors` 会把这些门全关上 —— 这其实是对的（酒坊雨天关门），
     但要写进 README，别让人以为坏了。
4. **室内会黑** —— 这一步最大的风险。领地材质全部带 `userData.noBake`
   （`townMaterials()` 里每个 `M()` 都设了，`src/bake.js:33` 据此跳过烘焙），
   空壳里只剩 HemisphereLight + 天光，阴影处黑到读不出设备。
   回廊已经踩过这个坑（README 记着"实测屋面底面 RGB 1,2,2"，才加了 `cloWall`
   那四条自发光材质当漫射补光）。**照抄这个办法**：给酒坊内壁/地坪/设备另开一套
   `"brew"` 前缀的半室内材质，带一点 `emissive`。
   **不要**为此把酒坊塞进烘焙（BAKE_VER 与 IndexedDB 缓存会失效、Worker 时间翻倍）。
5. 门洞净宽 ≥ 1.2 m，否则 `src/grid.js` 那张 1.4 m 一格的碰撞网格让不开。

### 第 4 步 · 葡萄园与酒花（**果子必须有，这是用户直接点出来的**）

**葡萄园** `buildVineyard()` —— 行端 x 57.5…72.5 / z -65.5…-76.7（建成后的实际值）：

- 5 行沿 x，行距 2.8 m，行长 15 m；行起点 z=-65.5 是为了让开葡萄酒窖北墙（-62），
  留 3.5 m 当运葡萄的步道。矮桩距 2.5 m（每行 7 根、高 1.9 m），桩上两道铁丝（0.9 / 1.8 m）。
- 藤冠：每行一条压扁的绿带（0.34 × 0.30，`mats.vine`，y 1.62），读起来就是一行修剪过的葡萄。
- **葡萄串**：沿下行铁丝每 0.8 m 一串（每行约 18 串），每串 14–17 颗小球
  （`grape = M('#5e3160')`；两成是白葡萄 `grapeW = M('#a8ad6a')`，免得一色紫像塑料）。
- ⚠️ **必须 `InstancedMesh`**：5 行 × ~18 串 × ~15 颗 ≈ 1350 颗，分紫 / 白两个实例组。
  独立 Mesh 会把 `src/grid.js` 的射线网格和七个检查器全拖垮。
  果粒是低面二十面体 r = 0.07 —— **不能再小**，0.05 时在阴影里远看就是"这园子没结果子"。
- 采收筐 3 个（x 73.1, z -67.5）+ 一架木梯；挪过来的遮荫树落在 **(52,-72)**，
  也就是东排住宅（x ≤ 45.1）与葡萄园（x ≥ 56）之间那条 11 m 空带。

**酒花圃** `buildHopYard()` —— 两处，都要挂出**酒花球果**：

- **主圃**（杆在 **x 57.6 与 60.0**，z **-62…-41**，21 m）：2 行沿 z，杆距 2.5 m、杆高 3.5 m，
  顶铁丝 3.3 m 挂垂吊**酒花球果**（每 2 m 一小簇 3–4 颗，`hopCone = M('#8fa23f')`，同样 Instanced）。
  位置在服务巷东口的左手边，且**在 LANE.z0 = -40 以北**，碰不到修士动线。
  藤冠压到 0.5 m：离巷东缘的明沟（x 61.0）还差 0.75 m。
- **巷边一行**（杆 **x = 56.9**，z **-28…65**，93 m）：沿服务巷西缘。
  ⚠️ 净宽只有 1.5 m（x 56…57.5），藤冠 **0.5 m** 以内，
  离修士动线 x=59.0 留 1.6 m —— `check-npc.mjs` 会验。
- 沿用旧圃那套杆 + 铁丝的形式（`mats.lead` 铁丝、`mats.timber` 杆）。

### 第 5 步 · 演示页 `tools/brewprocess.html`

照 `tools/drainage.html` / `tools/brewery.html` 的骨架：

- 透视墙体 + 工序列表 + 阶段按钮 + 相机飞行 + 字幕。
- 一颗高亮的**麦粒**沿啤酒线跑一遍、换一颗**葡萄**沿葡萄酒线跑一遍，
  走过每座房子时高亮屋里的对应器具。
- 坐标全部来自新增的 `brewInfo().process`——
  与真实模型同源一份数据，跟 `drainageInfo()` 同一个套路，别破例。
- 工序次序：啤酒 麦粒 → 粮仓 → 烘干窑 → 麦芽楼 → 煮酒房 → 冷却发酵 → 酒窖；
  葡萄酒 葡萄 → 葡萄园 → 压榨房 → 葡萄酒窖（回指酒肆）。

**建成后的实现要点**（补记）：

- **走线点**取每道工序在巷边的门口点 `b.x0 - 2.6`（葡萄园没有房子，用 `out.x + 12`）。
  两条线的门口点全落在服务巷（x 57.5…61.5）或它西边的空地，所以原料**不穿墙**，
  也不会横穿葡萄酒窖（那座 x ≥ 62.4）。
- 机位跟随时用固定偏移 `(-11, 7.5, -8)`：站在巷子西边、略高，正对那排房子。
- **器具高亮**：`buildBrewery()` 给每座房子的组挂 `userData.brewKey`，
  页面按它把 `userData.gear` 的网格分组；点亮时**克隆材质**加 emissive。
  克隆出来的新材质不在 `ghost` 名单里，所以开着透视时它是唯一不透明还在发光的东西。
- 阶段点击 = 相机飞到 `out`、视线落到 `in`（`gearAnchor()`，屋内中线眼高 1.7 m），
  因为射线要穿西墙，**透视墙体默认开**。
- 调试钩子：`window.__goto(key)` / `__run('beer'|'wine')` / `__view(...)` / `__xray(on)`，
  无头截图脚本靠它逐站取证。

顺带修掉的两个**真 bug**（都不是本轮引入的显式任务，但挡在验收路上）：

1. `wallSlab()` 门洞侧片的中心公式写成 `-half - dw/2 + side/2`，多减了一次 `dw/2`。
   后果：每座房子的门两侧各空出一道 **1.8 m 宽、通高的口子**，北墙还越过山墙伸到屋外 1.8 m。
   单看一座只像"墙比房子长一点"（既有六座 x0 错开成 62/63/64，墙片落在不同平面上，从没报过 z-fight）；
   新加的葡萄酒窖与压榨房 x0 都是 62.4，伸出去的两段正好落在同一张 x 平面上 → 严格模式报 2 处 7.7 m²。
   改成 `-half + side / 2`（各段自己的中点）后严格模式归零，八座的北墙也都补严了。
2. `brewInfo().drain.culvert` 还写着死的 `z0:-46.4, z1:-40`，而几何那边已经由 `chZ0`/`soak` 现算。
   `check-brew`/`check-rain` 读的是 mesh 包围盒所以照过，**`tools/brewery.html` 读的是 brewInfo** ——
   演示页的水会飞进一根不存在的管子里。抽成 `brewCulvert()`，几何与 brewInfo 共用同一份计算。
